# Задачи

Открытые задачи. Подробности сделанного в коде, в git и в документах `03`–`05`.

## Сделано

- Вход через Google, сессии в БД, автосоздание личного календаря.
- Несколько календарей, участники и роли, приглашения по одноразовой ссылке.
- Годовой вид на FullCalendar с растущими неделями, перенос и ресайз, многодневные события.
- Диалог события с автосохранением, выбор времени, отметка «выполнено», иконки, категории и теги.
- Повторяющиеся события с областями «только это», «это и последующие», «все».
- Архив вместо удаления с «Отменить», удаление переносом в корзину, поиск событий, экспорт в XLSX.
- Темы, три языка, мобильный вид (месяц, день с почасовой шкалой, свайпы).
- PWA и страница «Нет подключения» вместо выхода при ошибке сети.
- Docker Compose для прода, Caddy с HTTPS, `helmet`, лимиты запросов, CI в GitHub Actions.

## Рефакторинг

Делим по задачам со своими данными и своей частью шаблона, а не по типу кода. Начинать с файла, только когда параллельная работа над ним закоммичена.

- [ ] Страница календаря (`calendar.ts` около 900 строк, шаблон 325): навигация по периоду в отдельный компонент `calendar-period-nav` (меню года и месяца, мобильная панель «месяцы ↔ годы», фокус, подписи периода и стрелок; на входе `viewDate`, `isMobile`, `isDayView`, наружу «назад», «вперёд», «выбрана дата», «к месяцу», вызовы API FullCalendar остаются в странице).
- [ ] Страница календаря: шапка на виджеты (название календаря с переименованием, кнопки действий с меню), карточка события из `#eventContent` в компонент, корзина удаления перетаскиванием в компонент.
- [ ] Экспорт XLSX (`exportEvents`, `toExportLabels`, `toExportFileName`) из страницы в диалог экспорта или `utils`.
- [ ] `event-tags` (шаблон около 300 строк): список категорий события, выбор тега с поиском, меню управления категорией и тегом отдельными компонентами.
- [ ] Диалог «Поделиться» (около 210 строк): блоки «Пригласить по ссылке», «Участники», «Активные ссылки» отдельными компонентами.
- [ ] Диалог события (около 190 строк): блок дат и времени и блок повтора отдельными компонентами, если после разделения `event-tags` диалог останется большим.

## Позже

- [ ] Отмена по Ctrl+Z через снимки на сервере: перед каждым изменением события в той же транзакции пишется `EventRevision` (событие, исключения, теги, `id` новой части при делении серии), ответ возвращает `revisionId`, отмена через `POST /events/revisions/:id/restore` одной транзакцией. Один снимок на одно открытие диалога (автосохранение не плодит шаги). 409, если событие изменили после снимка (`updatedAt`). Глубина 20 шагов на пользователя, снимки старше суток удаляются при записи нового. На фронте стек `revisionId` в signal, Ctrl+Z вне полей ввода, кнопка «Отменить» в уведомлении.
- [ ] Ручная сортировка событий внутри дня. Пока не нужна. Набросок (по схеме Todoist): события со временем идут по времени, на весь день в ручном порядке; новое и перенесённое на другой день встаёт в конец дня; порядок в `Event.position` (`Float`), при переносе внутри дня среднее между соседями; в FullCalendar `eventOrder` сначала по позиции.
