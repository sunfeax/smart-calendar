# Стек

Версии не фиксируем в документе. При старте берём актуальные стабильные и проверяем совместимость (FullCalendar поддерживает Angular 16–22).

## Фронтенд

- **Angular** (standalone-компоненты).
- **Реактивность**: signals и RxJS, в зависимости от задачи:
  - **signals** для состояния (кто вошёл, выбранный период, открытые диалоги), шаблоны и `computed`;
  - **Observable** для HTTP и потоков событий во времени: запросы, отмена, повторы, debounce. `HttpClient` отдаёт Observable, методы сервисов возвращают его же;
  - переход между ними: `toSignal` (Observable → signal) и `toObservable` (signal → Observable). Подписки закрываются через `takeUntilDestroyed` или `async`-pipe.
- **Работа с данными** (стандарт для всех фич):
  - **сервис-API** (`@Service()`) только делает запросы и возвращает Observable, состояния не хранит. Компоненты не используют `HttpClient` напрямую;
  - **данные страницы** загружает `rxResource` в компоненте: он даёт `isLoading()`, `error()`, `value()`. Параметры (например, видимый диапазон дат) передаются через `params`: при их смене запрос повторяется, а устаревший отменяется;
  - **общее состояние приложения** (например, кто вошёл) хранится в signal внутри сервиса, потому что его читают несколько мест;
  - **UI-состояние** (фильтры, открытые панели) хранится в signals компонента, производные значения считаются через `computed`;
  - **мутации**: подписка всегда с обработкой ошибки. После успеха данные обновляются локально через `resource.update(...)` ответом сервера (добавить, заменить или убрать элемент), без `reload()` диапазона. Это касается и диалога, и переноса, ресайза, отметки «выполнено». Перенос и ресайз при ошибке откатываются через `revert()` FullCalendar. Когда появятся общие календари, вернуться к вопросу, как подтягивать изменения других участников (`04-calendar-frontend.md`);
  - **тексты** в шаблонах только через i18n.
- **Angular Material** + CDK (диалоги, выбор даты, меню, формы). Тёмная и светлая темы через тему Material.
- **FullCalendar v7**:
  - установка: `npm install --save @fullcalendar/angular@7 fullcalendar@7 temporal-polyfill`
  - пакет `fullcalendar` напрямую не импортируем, только `@fullcalendar/angular`
  - нужны плагины видов (месяц, при необходимости multi-month) и тема. Темы v7: Breezy, Forma, Monarch, Pulse, у всех есть тёмные варианты. Точные пути импортов смотреть в доках v7, а не в туториалах под v6
  - платные плагины (resource-timeline и т. п.) не нужны
- **i18n**: Transloco (`@jsverse/transloco`): смена языка на лету, JSON-файлы по языкам в `public/i18n/`. Языки ru, en, es, резервный ru. Настройка в `core/config/language.config.ts`, выбор языка в `LanguageService`. `@angular/localize` собирает отдельные бандлы на язык и для переключения на лету не подходит; ngx-translate тоже рассматривали, Transloco выбран из-за официальных плагинов для множественного числа и проверки ключей.
- **Шрифт**: Inter из пакета `@fontsource-variable/inter` (вариативный, с кириллицей, лежит в бандле). Иконки: Material Symbols Outlined.
- **Стили**: дизайн-токены в `src/styles/_tokens.scss`, тёмная тема через `data-theme='dark'` на `<html>`. Токены Material (`--mat-sys-*`) привязаны к нашим, поэтому компоненты Material берут наши цвета.
- **Даты**: `date-fns`; `temporal-polyfill` нужен FullCalendar.
- **Повторы**: `rrule` (строки формата RFC 5545). Плагин FullCalendar для rrule проверить в доках v7.
- **Иконки**: Simple Icons (`simple-icons`) для брендов, Lucide или Material Icons для общих значков, эмодзи.
- **Клиент API**: генерация из OpenAPI (Swagger) бэкенда, чтобы не дублировать типы вручную.

## Бэкенд

- **NestJS** (модули, DI, guards, pipes).
- **Prisma** + миграции (`prisma migrate`).
- **Валидация**: `class-validator` + `class-transformer`, DTO на каждый эндпоинт.
- **OpenAPI**: `@nestjs/swagger`.
- **Авторизация**: `google-auth-library` (проверка Google ID token), `cookie-parser`. Сессия хранится в таблице `Session`, токен в httpOnly-cookie. JWT не используем (`00-overview.md`).
- **Безопасность**: `helmet`, `@nestjs/throttler` (лимиты запросов).
- **Конфиг**: `@nestjs/config`, секреты в переменных окружения.
- **Тесты**: Vitest. Пока тестов не пишем.

## База данных

- **PostgreSQL** в Docker для локальной разработки.
- Даты: `timestamptz`.
- Позже при необходимости `pgvector` в той же БД.

## Инфраструктура

- **Docker Compose**: Nest + Postgres + обратный прокси.
- **Один домен** для фронтенда и API (API по пути `/api`) через Caddy или nginx. Так нет проблем с CORS и cookie.
- **HTTPS**: Let's Encrypt (Caddy делает автоматически).
- **Бэкапы**: `pg_dump` по расписанию и копия в другое место.
- **Хостинг**: VPS (Docker Compose: Nest + Postgres + Caddy).
- **Google OAuth**: проект в Google Cloud Console, Client ID. Для закрытой беты хватает режима Testing (до 100 тестовых пользователей). Для публичного запуска перевести в Production: нужны свой домен, политика конфиденциальности и проверка бренда. С базовыми scope (`openid`, `email`, `profile`) полная проверка приложения не требуется.

## Отвергнутые варианты

- Firebase/Supabase: не дают освоить серверный код.
- SQLite: подошёл бы по объёму, но Postgres ближе к реальной практике и совместим с будущим `pgvector`.
- Свой календарь с нуля: многодневные события, ресайз и раскладка полос слишком трудоёмки. Проверка FullCalendar пройдена, запасной вариант не нужен.
- Загрузка картинок в БД: заменена на встроенные иконки, эмодзи и ссылки.
- Вход по паролю: не нужен.
- JWT для сессий: отзыв сессии требует чёрного списка или refresh-токенов в БД. Выбрана сессия в таблице `Session`.
